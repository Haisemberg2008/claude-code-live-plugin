## Broker review during run07

P1 concurrency races: `startRun` checks for an active task run, then awaits realpath/inventory/state work before assigning `task.run`; two concurrent starts for the same task can both pass and spawn workers. The cross-task writer-lock check is likewise separated from `locks.set` by awaited filesystem work, so two tasks targeting the same checkout can both acquire it. Reserve task and canonical checkout atomically before any awaited preparation, and release reservations on every failure path. Add concurrent-start tests for same task and same checkout.

P1 event ordering/replay: global sequence numbers are assigned before independently awaited per-task log appends, allowing global sequence 2 to broadcast before sequence 1; the SSE hub then drops the late sequence as stale. Serialize durable append plus broadcast in global sequence order. Reconnect currently reads only the first 100000 records per task and then takes the last 2000, which can silently omit a cursor gap and ignore newer records in larger logs. Preserve cursor continuity or explicitly signal reset/resync; do not silently lose events. Bound replay buffering itself, not only post-replay socket buffering.

P1 accepted-message loss: enqueue accepts guidance while a worker exists but is not ready, yet the worker-ready callback clears the pending message collection. A202 response must mean durable queued delivery, not disappearance. Preserve and flush pre-ready messages in order, with restart/recovery semantics and a behavioral test.

P1 auth-policy cache bypass: broker preflight reuse is keyed only by model. A job that permits API billing can cache READY while API credentials are present; a later same-model job with `allowApiBilling:false` skips auth-path assessment and can spawn with inherited credentials. Cache only immutable CLI capability/probe evidence and reassess the per-job billing/auth policy against the actual spawn environment on every launch.

P1 process ownership/recovery: startup recovery kills a saved live PID without validating process identity/start time, so PID reuse could terminate an unrelated process. Worker exit also releases the writer lock without proving descendants were reconciled; a surviving Claude/tool child could continue mutating outside the lock. Persist and validate process identity, own a killable process tree/job object, and reconcile or quarantine descendants before releasing locks. Add simulated stale-PID and orphan-child tests without touching unrelated real processes.

P1 MCP framing/startup: `src/mcp/main.ts` imports `ensureBroker` from `cli/main.ts`, whose unguarded module-level `main()` runs on import. Normal MCP arguments contain no CLI command, so human usage text is written to stdout and corrupts JSON-RPC framing. Move reusable broker bootstrap out of the executable entrypoint and guard all mains. `ensureBroker` also lacks a cross-process startup mutex; simultaneous adapters can each spawn a broker, and each broker recovery can interfere with the other's workers. Add a true simultaneous-start test, not only sequential reuse.

P1 uncertainty recovery: persisted `UNCERTAIN` is not restored as `uncertain/requiresReview`; reopening initializes both false, so a broker restart can erase the mandatory acknowledgement and allow a new run. Preserve uncertainty durably until an explicit scoped acknowledgement/review. Recovery must first scan every task log to establish the global sequence high-water mark, then append recovery events; the current task-by-task scan/append can reuse a sequence that already exists in a later task log.

P1 lifecycle race: finalize marks the old run finalized before its awaited event/cleanup completes, so a new start may begin meanwhile. Old cleanup then reads mutable `task.worker`/current-run state and can terminate or overwrite the new run. Capture immutable run-owned resources and serialize start/finalization/exit transitions per task through completion; stale callbacks must be ignored by run identity.

Broker authorization boundary: loopback binding, Host checks, browser Origin/CSRF, browser task scope and MCP handle equality are present. However broker-level shutdown and handle registration/rotation only reject browser identities, allowing a generic identity tagged `mcp`; global lock inspection is also exposed at route level. Even if current MCP tools do not call these routes, privileged lifecycle/bootstrap endpoints must require the local administrative secret explicitly, and global state should follow least privilege.
